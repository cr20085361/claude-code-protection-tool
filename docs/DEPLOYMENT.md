# 部署与构建边界

当前源码为 v1.3.3，初始化中的节点和目录使用示例值。当前没有跨机器一键部署验收，不提供将此仓库克隆后直接修改全局环境的自动安装流程。

## 首次部署前

1. 核对官方 Windows x64 Claude Desktop 包及其签名、版本和包身份。不要使用第三方修改包。
2. 审查 `ClaudeGuard.psm1` 的 `Initialize-Guard`：将示例固定节点地址和 v2rayN 配置/核心/界面配置路径替换为本机实际值；同时核对节点出站类型和物理网卡选择。`192.0.2.10` 是示例地址，不能作为真实出口使用。
3. 确认可以备份、回读当前账号的代理策略、已有 CLI 配置、Code 缓存权限和自有防火墙规则。初始化会拒绝覆盖已经存在的专属配置，并拒绝不兼容的机器级策略/PAC。
4. 选择本机 PowerShell 7.4 或以上的实际 `pwsh.exe` 路径，保存在受限的 `private/launcher-paths.txt`。该文件是本机状态，不提交 Git。
5. 先完全退出 Claude Desktop 和本地 Code，再分阶段部署；管理员授权使用同一 Windows 账号。不要复制作者机器的部署记录、账号目录或节点文件。

## 文件与阶段

| 阶段 | 相关文件 | 需要核对的结果 |
|---|---|---|
| 本机初始化 | `Initialize-ClaudeGuard.ps1` | 专属配置、受限目录、实际包身份及保护哈希 |
| 策略和 Desktop 防火墙 | `Install-ClaudeFirewall-Admin.ps1`、`Install-ClaudeGuard.ps1` | 同账号桌面上下文回读及实际连接 |
| Code 缓存与执行门禁 | `Prepare-ClaudeCode.ps1`、`Finalize-ClaudeCode-Admin.ps1` | 包内指定版本、校验值、缓存路径、权限及规则 |
| 编译入口/宿主 | `Build-ClaudeShortcut.ps1` | x64 程序、图标、快捷方式及实际入口启动 |
| 后台守护和版本迁移 | `Update-ClaudeGuard.ps1` | 操作/候选/结果关联、任务配置、当次健康及固定出口 |
| 真实客户端验收 | 入口、运行证据与独立 Code 会话 | 启动/检查/重开、实际程序环境及 TCP、Code 正常响应 |

该表用于理解依赖关系，不能视为已经通过的全新机器安装步骤。现有缓存、账号和权限状态不同，需要先检查对应脚本的拒绝条件。编译脚本要求入口和自有宿主退出，不能在正在运行的生产部署上直接重建所有程序。

第三方程序（Claude Desktop、配套 Code、代理核心及系统网络探针）没有随仓库再分发；各自下载、许可、签名及哈希由部署过程核对。项目 MIT 许可适用于此仓库自有源码，不替代第三方软件许可。

## Xray 节点池边界

当前代码支持 `ProxyEngine=xray` 的已核准节点池，核心位于本机 `runtime/xray.exe`，配置仍为 `private/proxy.json`，部署记录以 `ExpectedIps` 保存允许的出口。`New-GuardXrayNodePool` 接受具有显式 IPv4 地址的 VLESS Reality RAW/TCP 节点，生成只监听回环地址的独立代理、连接探测及拒绝回退配置。旧部署不含这些字段时继续使用 sing-box 和 `ExpectedIp`。

首次初始化仍沿用上面的单节点流程；节点池导入和现有部署迁移尚没有通用一键安装器。变更须备份原状态，在停止客户端和暂停自有守护后核验核心、配置、出口及部署哈希；维护或恢复不得悄悄更改节点池边界。共享客户端中的新节点不会自动加入核准列表。本机双节点成功记录不能代替其他节点、其他协议或其他机器的验收。

入口编译时使用源码绝对路径。部署前可执行 `Test-ClaudeSupervisorHealth.ps1 -LauncherAssembly <入口EXE绝对路径>`，直接验证最终程序的健康契约，避免只检查源码生成的测试库。

## 日常使用与更新

部署及实际入口验收完成后，日常双击 Claude Pro 安全入口，等待检查通过再使用。下方显示安装、配套、已核准与实际观察到的本地 Code 版本。

“检查新版”查询官方当前发布；“下载官方包”下载并核验 Desktop 和其配套 Code，下载可在入口关闭后继续。“安装并维护”只对已经核验的更高版本启用，要求完全退出客户端，经同账号管理员授权后自动完成必要的安装前维护、安装、版本防护迁移和守护核验。健康状态下跳过安装前维护；无需先手动点击“维护版本”。

安装前和授权后均检查 Desktop/Code 会话。主窗口退出后仍可能有 MSIX 后台服务占用包；安装使用 Windows 的 `-ForceTargetApplicationShutdown` 关闭目标 Claude 包关联的活动进程，再同步安装并回读实际版本。该步骤可能结束目标包后台任务，因此应先保存工作并退出客户端。

若 Windows 仍返回 `0x80073D02`，仅在旧客户端版本、路径、哈希、包身份及部署基线均确认未变且防护备份恢复成功时，保留已核验包并开放“安装并维护”重试。安装结果无法确认或恢复失败时，仍要求“维护版本”恢复。完整错误及 Windows ActivityId 保存在本机维护记录中，界面提供简短原因和诊断 ID。

v1.3.0 已产生的资源占用失败可能留下安全暂停。已核验的失败包可直接点击“安装并维护”，恢复防护后自动接续安装，无需重新下载。独立的“维护版本”仍用于单独修复和明确中断操作的恢复。真实策略、签名、出口或恢复核验未通过时，组合流程停止并保留失败记录。

入口每两秒根据本机 Claude Desktop 包的进程身份刷新启动按钮。手动退出后显示“打开 Claude”；安装期间显示“更新进行中”；安装完成后根据实际进程恢复显示，关闭入口不会退出客户端。

维护可能超过两分钟。超过观察预算但进程仍运行时继续等待；只有明确 Windows 授权取消才显示取消。安装或维护中断时从“维护版本”进入管理员恢复。备份恢复的是防护配置、权限与任务，不能保证恢复系统已经删除的旧 Desktop 程序。

版本显示、代理监听、旧成功记录均不能代替当前安全就绪检查。请分别验证新版 Code 会话、睡眠唤醒、重新登录和长期连续使用。
